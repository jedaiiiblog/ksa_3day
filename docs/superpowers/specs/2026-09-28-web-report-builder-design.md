# 팀 주간 보고 웹 입력 → PPT 생성 설계

> 기획서 `팀_주간보고_취합_기획서.md`의 취합·기여도·PPT 로직을 웹 화면으로 옮긴다. 기획서 §8의 "입력 화면 제작"이 이번 범위에 포함된다. 기존 Python 구현(`team_report/`)은 그대로 둔다.

## 1. 목표와 합의된 결정

- **목표:** 팀 취합 담당자가 웹 화면 하나에 팀원별 프로젝트·주간 내용, 공휴일·휴가, 요약을 입력하면 상위부서 보고용 PPT(.pptx)를 내려받는다.
- **실행 방식:** 서버 없음. `web/index.html`을 더블클릭해 브라우저에서 연다.
- **입력 주체:** 담당자 한 사람이 한 화면에 모두 입력한다. 팀원별 파일 전달·불러오기는 이번 범위가 아니다.
- **요약:** 담당자가 프로젝트별로 직접 쓴다. AI 자동 호출은 없다.
- **유지:** 기여도 공식과 PPT 구성(팀 요약 1장 + 팀원별 1장)은 기획서 그대로다. 기여도는 코드가 계산한다.
- **하지 않는 것:** 팀원 각자 접속/제출, 파일 가져오기(md), 서버·계정, 자동 발송·알림, 반차, 휴가 기간 범위 입력, 순위·인사평가, 월 외 기간, 이미지·차트 슬라이드.

## 2. 파일 구조

```
실습/web/
  index.html            # 화면 뼈대, 스크립트 로드
  style.css
  core.js               # 순수 로직: 날짜, 근무일, 기여도, 정규화, 마감 판정, 경고, 검증, 저장 형식
  deck.js               # PptxGenJS로 슬라이드 생성 (core 결과를 입력으로 받음)
  app.js                # 화면 상태, 렌더링, localStorage, 백업 저장/불러오기
  vendor/pptxgen.bundle.js   # 오프라인용 PptxGenJS (npm에서 1개 파일 복사, 받기 전 사용자 허락)
실습/web-tests/
  core.test.js          # node --test
  deck.test.js
```

- `file://`에서 ES 모듈 import가 막히는 브라우저가 있으므로 빌드 없이 일반 `<script>` 태그로 로드한다. `core.js`와 `deck.js`는 브라우저에서는 `window.TR`에 붙고 Node에서는 `module.exports`로 내보내는 방식으로 만든다.

## 3. 화면 (한 페이지, 위에서 아래로)

1. **기본 설정:** 대상 연·월, 마감 시각(기본 17:00).
2. **달력:** 공휴일(날짜 + 이름) 추가/삭제, 팀원별 휴가일 추가/삭제. 이름은 팀원 카드의 이름 중에서 고른다.
3. **팀원 카드**(추가/삭제 가능):
   - 이름
   - 보고 목록(주 단위 추가/삭제): 주차 날짜(금요일), 제출 시각(기본값 = 카드를 만든 시각, 수정 가능), 프로젝트 목록(프로젝트명 + 주간 내용)
   - **월 요약:** 그 팀원의 월 내 프로젝트(이름 정규화로 중복 제거)마다 요약 입력 칸 하나
4. **팀 요약 문장:** 팀 전체 요약 입력 칸 하나.
5. **확인 패널**(입력할 때마다 갱신): 팀원별 프로젝트 목록·개수, 근무일, 월 기준 시간, 팀 대비 %, 프로젝트당 시간·개인 기준 %·프로젝트 팀 대비 %, 지연 제출 표시, 경고 목록, 차단 사유 목록.
6. **PPT 만들기 버튼**과 **백업 저장 / 백업 불러오기 버튼.** 경고가 남아 있으면 PPT 생성 전에 확인 대화상자를 한 번 띄운다.

## 4. 데이터

상태(JSON, 스키마 버전 `v: 1`):

```
{ v, year, month, deadline: "17:00",
  holidays: [{date: "YYYY-MM-DD", name}],
  vacations: [{ name: "이름", date: "YYYY-MM-DD" }],   // 화면의 반쯤 채워진 행을 다루기 위해 배열로 저장
  members: [{ name, reports: [{ week: "YYYY-MM-DD", submittedAt: "YYYY-MM-DDTHH:MM",
                               projects: [{ name, body }] }] }],
  summaries: { team: "", projects: { "<정규화 이름>|<정규화 프로젝트>": "요약" } } }
```

- **자동 저장:** 변경 후 짧은 지연(300ms)으로 localStorage(`teamReport.state`)에 저장. 불러올 때 JSON이 깨졌거나 `v`가 다르면 빈 상태로 시작하고 화면에 알린다(저장된 원본은 덮어쓰기 전까지 삭제하지 않는다).
- **백업:** 상태 JSON을 `팀보고_백업_YYYY-MM.json`으로 내려받고, 불러오기는 같은 스키마를 검증한 뒤 현재 상태를 교체한다(교체 전 확인). 잘못된 파일이면 상태를 바꾸지 않고 사유를 보여 준다.
- 날짜는 `YYYY-MM-DD` 문자열로 저장하고 계산은 UTC로 한다(시간대 때문에 하루가 밀리지 않게).

## 5. 계산 규칙 (Python `calc.py`와 동일)

- 1인 하루 8시간. 개인 월 기준 시간 = (해당 월 월~금 일수 − 공휴일 − 그 팀원 휴가일) × 8. 주말 날짜, 다른 달 날짜, 공휴일과 휴가가 같은 날인 경우는 한 번만 뺀다.
- 프로젝트 수 = 그 팀원의 월 내 보고 전체에서 정규화한 프로젝트 이름의 합집합 크기. 정규화 = 앞뒤·중복 공백 정리 + 소문자화.
- 프로젝트당 시간 = 개인 월 기준 시간 ÷ 프로젝트 수. 개인 기준 % = 100 ÷ 프로젝트 수. 팀 대비 % = 개인 시간 ÷ 팀 합계. 프로젝트 팀 대비 % = 프로젝트당 시간 ÷ 팀 합계.
- 프로젝트 0개이거나 팀 합계 0이면 해당 값은 0(0으로 나누지 않음).
- 대상 월에 해당하는 보고만 사용한다(주차 날짜의 연·월 기준). 다른 달 주차 보고는 무시하고 확인 패널에 "무시됨"으로 알린다.
- **마감 지연:** 제출 시각 > (주차 날짜 + 마감 시각)이면 지연. 정확히 마감 시각이면 지연 아님. 지연은 제외가 아니라 표시만 한다.
- **팀원 순서:** 그 팀원의 대상 월 보고 중 가장 이른 제출 시각 순. 같으면 입력 순서.

## 6. 경고와 차단

경고(생성 가능, 확인 대화상자):
- 팀원 수가 5명이 아님
- 휴가 명단의 이름이 팀원에 없음
- 주차 날짜가 금요일이 아님
- 요약이 비어 있는 프로젝트가 있음
- 다른 달이라 무시된 보고가 있음
- 한 팀원의 프로젝트 이름이 정규화하면 같지만 표기가 다른 경우(같은 프로젝트로 합쳐졌음을 알림)

차단(버튼 비활성 + 사유 표시):
- 팀원이 0명, 이름이 비었거나 팀원 이름이 중복(정규화 기준)
- 대상 월에 보고가 하나도 없는 팀원, 프로젝트명이 빈 항목
- 날짜 형식이 잘못된 공휴일·휴가·주차, 제출 시각이 비어 있음
- 연·월이 유효하지 않음

## 7. PPT (PptxGenJS)

- 슬라이드 크기 16:9, 글꼴 "맑은 고딕".
- **슬라이드 1:** 제목 "{연}년 {월}월 팀 주간 보고 취합", 표(팀원 / 프로젝트 수 / 월 기준 시간 / 팀 대비 비중), 팀 요약 문장(비어 있으면 "(요약 없음)").
- **팀원별 슬라이드:** 제목 "{이름} — {연}년 {월}월", 표(프로젝트 / 요약 / 시간 / 개인 기준 % / 팀 대비 %), 하단 메모(근무일·월 기준 시간·팀 대비 %, 지연 제출이 있으면 해당 주차).
- **넘침 방지:** 한 슬라이드에 프로젝트 6개까지. 초과하면 "{이름} — {연}년 {월}월 (계속)" 슬라이드로 나눈다. 요약이 없으면 `(요약 없음) ` + 내용 앞 200자(초과 시 `…`).
- 시간·비율은 소수 1자리(`53.3h`, `21.1%`). 파일명 `팀_월간보고_YYYY-MM.pptx`.

## 8. 테스트와 검증

- **`core.js` (node --test):** Python 테스트와 같은 값 — 근무일 22 / 20 / 18, 기획서 예시(160h, 프로젝트당 40h, 21.1%), 팀 비중 합 100%, 0 나누기 방지, 이름 정규화 병합, 17:00 정상·17:01 지연, 주말·다른 달·중복 공휴일·휴가 처리, 팀원 순서, 경고 각 항목, 차단 각 항목, 상태 검증(손상 JSON, 다른 버전).
- **`deck.js`:** 프로젝트 13개 팀원 → 슬라이드 3장(6+6+1)으로 나뉘는지, 생성된 .pptx가 Python `python-pptx`로 열리고 슬라이드 수·핵심 문구가 맞는지.
- **화면:** 내장 브라우저로 `web/index.html`을 열어 입력 → 확인 패널 → 백업 저장/불러오기 → PPT 생성 흐름을 직접 실행해 확인한다.
- **사람이 확인:** PPT 글자 배치·넘침은 PowerPoint에서 육안 확인(자동 검증 불가).

## 9. 미결정·가정 (틀리면 이 표만 고친다)

| 항목 | 가정 |
|---|---|
| 제출 시각 | 담당자가 카드에서 수정 가능, 기본은 카드 생성 시각 |
| 브라우저 | 최신 Chrome/Edge에서 `file://`로 열어 동작 |
| PptxGenJS 파일 | npm에서 받아 `web/vendor/`에 둠(받기 전 허락 요청) |
| 마감 후 파일 | 제외하지 않고 표시만 |
| 기획서의 남은 확인 사항(마감 시각, 제출 주기) | 기본값 17:00, 월말 1회 |
